# 开发产物管理

## 会话归档

Vibe coding 的计划、探针、临时脚本、实验结果、验证报告、截图、导出及其衍生版本统一写入仓库根的 `.local/sessions/`，整个 `.local/` 由 Git 忽略。

每个会话使用 `YYYYMMDD-HHMMSS-主题-短标识` 命名（北京时间）。短标识优先取会话 ID；无法获取时生成不重复标识。同一会话持续复用目录，不同会话即使主题相同也应分开。

```text
.local/sessions/20261030-120000-mining-a1b2c3d4/
├── README.md       # 主题、会话标识、开始时间、来源、结论及未完成验证
├── plans/          # 计划与分析草稿
├── scripts/        # 临时探针和一次性验证脚本
├── reports/        # 排查报告、验证结果与命令输出
├── shots/          # 截图、裁剪及标注衍生图
├── logs/           # 此会话主动运行的验证日志
└── exports/        # 导出文件及衍生版本
```

子目录按需创建。临时脚本应显式指定本会话输出目录；使用 `RunLogger` 时设置其 `base_dir`，避免重新产生旧 `artifacts/`。脚本执行仍以仓库根为工作目录，除非脚本明确约定其他位置。

## 正式文件与运行日志

- `docs/` 仅保留持续维护的架构、操作指南、任务流程与规范；`docs/assets/` 仅保留这些文档引用的正式素材。
- `tests/` 保留可重复运行的回归测试，`tests/fixtures/` 保留测试需要的代表性证据；业务使用的模板保留在对应子 bot 的 `templates/`。
- 会话结果需要成为正式成果时，将必要内容整理到上述位置，核对引用与验证边界后纳入 Git。正式文件不得链接到本地会话文件作为必要说明或运行依赖。
- 应用运行的 `logs/` 继续按原路径生成并由 `RunLogger` 执行七天保留策略，不改变正式程序行为。需要归档的会话证据应及时复制进会话目录；会话目录不自动套用日志清理策略。
- `*.log`、`*.log.*`、本机 `.env` 及开发工具缓存均忽略；`.env.example` 继续跟踪。不全局忽略 PNG、JSON、JSONL、Markdown，以免隐藏正式模板、测试数据和文档。

## 历史迁移

无法可靠确认原始会话 ID 的文件使用 `.local/sessions/legacy-主题/`，只表示历史主题分组，不声称属于同一个原始会话。保留原有子目录结构，便于还原旧报告中的路径；各归档 `README.md` 记录原位置与新位置。旧脚本和日志按历史证据原样保存，重新执行前须调整输出路径并复核设备参数。

本次迁移清单位于 `.local/sessions/20261030-artifact-organization/reports/migration.json`，记录文件路径与 SHA-256，用于核对内容是否完整。原有未提交报告也按工作区当前内容保存。

`artifacts/` 仅保留兼容忽略规则，新会话不再使用。Git 忽略规则不会自动取消已有跟踪：已跟踪的过程文件迁出后，Git 显示原路径删除；本地 `.env` 使用 `git rm --cached -- .env` 取消跟踪并保留文件。这些改动不清除 Git 历史中的旧版本。
